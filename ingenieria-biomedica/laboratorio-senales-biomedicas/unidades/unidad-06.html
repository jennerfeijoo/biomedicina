Desarrollo 1

Un flujo con contratos comprobables

El producto final no es una sucesión de celdas que solo funciona en la memoria de quien la ejecutó. Cada etapa recibe entradas declaradas y devuelve una salida con significado: lectura con unidades, máscara de calidad, transformación, eventos y características. El contrato especifica dimensiones, frecuencia de muestreo, unidades y tratamiento de ausencia. Si una etapa cambia el reloj, también actualiza los tiempos de sus salidas. La siguiente etapa no debe adivinar si un entero representa muestras originales, muestras remuestreadas o milisegundos.

La entrada original se conserva y las salidas derivadas se guardan por separado. La configuración describe canal, intervalo, filtro, tolerancias, regla de calidad y agregación. Un nombre como resultado_final no distingue dos ejecuciones con parámetros diferentes. En el laboratorio se asigna a cada ejecución un identificador y se almacena junto a configuración y resultados. No hace falta un sistema complejo para que otra persona pueda seguir qué archivo y qué decisión produjeron una cifra de la tabla final.

Las etapas deben fallar de forma informativa cuando no se cumplen sus condiciones. Una frecuencia no positiva, un arreglo vacío o un canal sin unidad requieren una decisión explícita. No se oculta la excepción produciendo una lista vacía de eventos y reportando sensibilidad cero: eso confundiría un problema de entrada con un fallo del detector. El registro de ejecución diferencia ausencia de datos, incompatibilidad de parámetros y resultado válido sin eventos. Esa distinción permite corregir la causa adecuada y evita métricas engañosas.

Puntos de integración

  • Declare unidades y dimensiones entre etapas.
  • Conserve entradas y derivados en rutas distintas.
  • Diferencie fallo de ejecución y resultado vacío.

Desarrollo 2

Procedencia, versiones y reproducción

Un hash criptográfico resume los bytes de un archivo y permite comprobar si esos bytes coinciden con los de una versión registrada. No demuestra que los datos sean correctos, que el consentimiento exista o que las unidades estén bien interpretadas. Por eso el manifiesto incluye además origen, versión, condiciones de acceso y metadatos. La documentación de hashlib permite calcular SHA-256; el laboratorio lo utiliza para identidad del archivo, sin presentarlo como certificación del contenido científico.

La configuración reproducible registra versiones de bibliotecas y parámetros explícitos. Un valor por defecto puede cambiar entre versiones; fijar la ventana de Welch o el eje del filtro evita depender de esa variación silenciosa. Cuando una operación contiene azar, se documentan generador, semilla y propósito. La semilla sola no garantiza resultados idénticos entre implementaciones o versiones. Conservar también entradas sintéticas generadas, o una referencia de sus bytes cuando se distribuyen, facilita distinguir cambios del generador de cambios del método analítico.

La reproducción se comprueba desde un proceso nuevo, no ejecutando únicamente la última celda. Se eliminan dependencias de variables creadas manualmente y se comprueba que el resultado se reconstruya con la documentación disponible. Para cálculos flotantes puede ser apropiada una tolerancia numérica en vez de identidad binaria, siempre que se justifique por la operación. Los datos y parámetros deben seguir siendo los mismos. Una tolerancia grande elegida después de ver una discrepancia no sustituye la investigación de su causa.

Puntos de integración

  • Un hash identifica bytes y no significado.
  • Fije parámetros que afectan la interpretación.
  • Reejecute desde un proceso sin estado previo.

Desarrollo 3

Particiones y ajustes sin información reservada

La partición responde al uso que se desea estudiar. Si se evalúa comportamiento en nuevas personas, los registros de una persona se mantienen juntos y no se reparten ventanas aleatoriamente entre conjuntos. Si se estudia generalización temporal dentro de una persona, se respeta el orden y se declara ese objetivo diferente. No existe una partición universalmente correcta para todas las preguntas. La lista explícita de identificadores por conjunto es parte del resultado y permite verificar que las afirmaciones de independencia tienen fundamento.

Las operaciones aprendidas de datos incluyen normalización, selección de características, ajuste del detector y elección de umbrales de calidad. Se estiman en desarrollo y se aplican a evaluación sin reaprender de ella. La documentación de scikit-learn explica esta separación y el uso de Pipeline para reducir errores de procedimiento. GroupKFold mantiene grupos no solapados entre particiones, pero no elimina automáticamente todas las vías de fuga: una estadística calculada previamente sobre el conjunto completo sigue contaminando la evaluación aunque los índices finales estén separados.

El conjunto de prueba no se convierte en entrenamiento informal al revisar repetidamente sus resultados para elegir la mejor configuración. Para decisiones iterativas se utiliza validación dentro del desarrollo; el test responde después una pregunta sobre el procedimiento ya fijado. Si se modifica el método tras inspeccionar el test, se reconoce que esa evidencia ya participó en desarrollo y se busca una nueva evaluación independiente. El informe conserva también configuraciones descartadas para que el resultado final no oculte cuánta selección ocurrió.

Puntos de integración

  • Defina generalización antes de separar datos.
  • Mantenga cada sujeto dentro de un conjunto.
  • No ajuste transformaciones con información reservada.

Desarrollo 4

Pruebas y un informe que admite fallos

Las pruebas más informativas tienen una respuesta conocida independiente del código que se está comprobando. La conversión afín debe llevar el código de referencia a cero; un cambio de unidades por factor mil debe multiplicar RMS por mil y potencia por un millón; una omisión sintética debe fusionar dos intervalos. Estos ensayos contrastan relaciones matemáticas y conectan las seis unidades. No basta comprobar que una función devuelve un arreglo del tamaño esperado, porque una escala equivocada puede conservar perfectamente ese tamaño.

Las pruebas adversas incluyen señal vacía, constante, con huecos, recortada y con eventos duplicados. También se evalúa un filtro cuyo relleno no cabe en la longitud del registro y una frecuencia de muestreo incompatible con los parámetros. Cada caso tiene un comportamiento esperado: rechazo informado, salida no definida o cálculo con máscara declarada. Guardar esos resultados hace visible el alcance del algoritmo. Un sistema que siempre produce un número puede ser menos fiable que otro que reconoce cuándo sus supuestos no se cumplen.

El informe integrador muestra procedencia, configuración, tiempo elegible, cobertura, conteos de eventos, métricas y ejemplos de error. Las figuras conservan ejes, unidades y la superposición de referencia cuando existe. La conclusión distingue tres niveles: el cálculo pasó pruebas sintéticas, el método obtuvo cierto resultado en una base concreta y todavía falta evidencia para otro contexto. Reproducir una cifra no demuestra utilidad clínica ni ausencia de sesgo. La entrega se considera académicamente auditable cuando otra persona puede reconstruir tanto el resultado favorable como el fallo documentado.

El script descargable incluido en las fuentes ejecuta un caso por unidad con la biblioteca estándar de Python. Guárdalo como signal_laboratory.py y ejecuta python signal_laboratory.py desde una terminal con Python 3.10 o superior. Compara las claves u1 a u6 de su salida JSON con los ejemplos del texto. Conserva esa salida, modifica un parámetro y explica la diferencia antes de repetir. El emparejamiento implementado prioriza el número de parejas y después su error total; su coste cuadrático limita su uso a ejemplos pequeños.

Puntos de integración

  • Use referencias independientes del código probado.
  • Incluya entradas que violan los supuestos.
  • Reconstruya resultados favorables y también adversos.

Ejemplos y casos resueltos

Cambio de unidades

Situación. Señal x en mV con RMS=2; convertirla a µV.

Razonamiento paso a paso

  1. Multiplicar amplitudes por 1000.
  2. Esperar RMS=2000 µV.
  3. Esperar potencia=4 000 000 µV² en vez de 4 mV².

Interpretación. La relación sirve para detectar errores de escala sin repetir el algoritmo interno.

Limitaciones

  • Se presupone conversión uniforme sin recorte ni redondeo adicional.

La partición aparentemente grande

Situación. Cuatro personas aportan cien ventanas cada una; se mezclan 400 ventanas y se divide al azar.

Razonamiento paso a paso

  1. Identificar las personas de cada ventana.
  2. Comprobar si alguna identidad aparece en ambos conjuntos.
  3. Rehacer la partición por persona si la pregunta trata personas nuevas.

Interpretación. Cuatrocientas ventanas no representan cuatrocientas personas independientes.

Limitaciones

  • Con cuatro personas la evaluación externa sigue siendo limitada aunque no exista fuga de identidad.

Actividad aplicada

Cuaderno de comprobación de pipeline reproducible

Procedimiento

  1. Trabaja con los datos sintéticos concretos de cada problema y conserva las operaciones.
  2. Consulta los criterios después de resolver; contrasta una condición modificada y explica el cambio.

Problemas y tareas

  • Ejecuta el script descargable y conserva la salida JSON de las seis unidades.
  • Duplica una predicción ya emparejada en el ejemplo y evalúa el efecto.
  • Introduce NaN en una entrada de RMS y registra el resultado esperado.
  • Construye una lista de ocho registros de cuatro sujetos y una partición por identidad.
  • Registra una configuración que incluya reloj, canal, filtro, máscara y tolerancia.
  • Calcula SHA-256 del archivo de entrada, cambia un valor y repite.
  • Reproduce desde un proceso nuevo sin variables previas y compara resultados con tolerancias declaradas.
  • Escribe una conclusión de tres frases distinguiendo cálculo, evidencia del conjunto y generalización pendiente.

Entregables

  • Tabla de resultados con unidades y procedimiento.
  • Figura o tabla que contraste el caso nominal y el fallo estudiado.

Criterios de comprobación

  • Comparar alias cercano a cero, cobertura 0,87, borde [1,2,3], TP=2, potencia de banda 20 y factor de potencia cercano a un millón.
  • No aumenta el número de referencias disponibles; aparece una predicción adicional sin pareja si las otras asociaciones se conservan.
  • Debe producir ValueError; no convertir ausencia en cero.
  • Comprobar conjuntos disjuntos de sujetos; dos registros por persona permanecen juntos.
  • Todos los valores deben estar explícitos, con unidades y versión; ninguna etiqueta se sustituye por un valor por defecto desconocido.
  • Conservar ambos hashes y versiones; una diferencia indica cambio de bytes, no explica si fue correcto.
  • Una discrepancia debe rastrearse a entradas, parámetros, versiones o aritmética antes de ampliar tolerancias.
  • No presentar pruebas sintéticas como validación clínica; incluir cobertura y un fallo observado.

Errores frecuentes y autoevaluación

Errores frecuentes y corrección

  • Guardar solo la figura final.

    Conservar entradas, configuración y resultados intermedios interpretables.

  • Presentar hash como garantía científica.

    Usarlo únicamente para identidad de bytes.

  • Partir ventanas mezclando sujetos para evaluar personas nuevas.

    Separar identidades antes del ajuste.

  • Ocultar excepciones con métricas por defecto.

    Distinguir fallos y salidas válidas no definidas.

  • Declarar validación clínica tras pruebas sintéticas.

    Limitar la conclusión al nivel de evidencia efectivamente obtenido.

1. ¿Qué garantiza igualdad de hash de dos archivos en el uso práctico descrito?

Respuesta: Identidad de bytes con la garantía criptográfica del método, no validez científica.

Razonamiento: Las unidades y la procedencia requieren metadatos adicionales.

2. RMS=3 mV. ¿Valor al expresar señal en µV?

Respuesta: 3000 µV.

Razonamiento: La amplitud se multiplica por mil.

3. Potencia=9 mV². ¿Valor en µV²?

Respuesta: 9 000 000 µV².

Razonamiento: El factor de amplitud se eleva al cuadrado.

4. ¿Puede calcularse la media de normalización con todos los sujetos antes de separarlos?

Respuesta: No para una evaluación reservada de un ajuste aprendido.

Razonamiento: Los sujetos de test aportarían información al procedimiento.

5. ¿Qué informar si el filtro no admite la longitud del registro?

Respuesta: Incompatibilidad y parámetros que la causan.

Razonamiento: No fingir una detección válida sin eventos.

6. ¿Una semilla garantiza identidad entre cualquier versión de biblioteca?

Respuesta: No.

Razonamiento: También importan generador, versión y secuencia de operaciones.

7. ¿Qué ocurre si se elige el umbral mirando repetidamente el test?

Respuesta: Ese conjunto participa en el desarrollo.

Razonamiento: Se necesita reconocerlo y obtener evaluación independiente.

8. ¿Qué demuestra repetir exactamente una métrica de una base concreta?

Respuesta: Reproducción de ese cálculo bajo sus condiciones.

Razonamiento: No demuestra generalización clínica ni ausencia de sesgos del conjunto.

Glosario disciplinar

  • Contrato de etapa

    Condiciones y significado de entradas y salidas de una operación.

  • Manifiesto

    Registro que vincula archivos, parámetros, versiones y ejecución.

  • Hash

    Resumen de bytes utilizado para comprobar identidad de contenido.

  • Configuración

    Conjunto explícito de decisiones y parámetros de una ejecución.

  • Semilla

    Entrada que inicializa un generador pseudoaleatorio específico.

  • Desarrollo

    Datos utilizados para ajustar y seleccionar el procedimiento.

  • Validación interna

    Comparación usada para decisiones dentro del desarrollo.

  • Test reservado

    Datos mantenidos fuera de ajustes para evaluar un método fijado.

  • Grupo

    Identidad que debe permanecer junta dentro de una partición.

  • Prueba adversa

    Ensayo con entradas que desafían supuestos del procedimiento.

  • Tolerancia numérica

    Diferencia admitida y justificada en una comparación de cálculo.

  • Reproducción

    Reconstrucción de resultados con las mismas entradas y procedimiento.

Conecta especialmente con El procedimiento se aplica a registros fisiológicos solo después de comprobar sus unidades, anotaciones y condiciones de adquisición, Los resultados sintéticos verifican operaciones matemáticas; la generalización a pacientes requiere evidencia independiente.
