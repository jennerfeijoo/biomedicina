Ingeniería de Datos Biomédicos

Curso completo de Ingeniería de Datos Biomédicos orientado a comprender, aplicar, verificar y comunicar sus métodos en problemas biomédicos. Integra teoría, casos, práctica reproducible, controles, incertidumbre, revisión y transferencia responsable.

Propósito formativo

Soporte para investigación, clínica, IA biomédica y sistemas de salud.

Prerrequisitos recomendados

  • Fundamentos de programación: variables, control de flujo, funciones y archivos.
  • Álgebra y razonamiento lógico de nivel universitario inicial.
  • Uso básico de terminal, control de versiones y documentación técnica.

Competencias del curso

  • Construir modelos conceptuales rigurosos en Ingeniería de Datos Biomédicos.
  • Aplicar el flujo definir uso y unidad de observación → modelar datos y significado → implementar transformación → validar técnica y clínicamente → vigilar desempeño a casos nuevos.
  • Seleccionar y documentar diccionarios, perfiles de datos, pruebas de interoperabilidad, métricas de desempeño, auditorías y evaluación de uso.
  • Diseñar controles, casos límite y análisis de sensibilidad.
  • Producir resultados reproducibles con procedencia, parámetros, versiones y registro de cambios.
  • Comunicar a audiencias académicas y generales sin exagerar evidencia ni alcance.

Objetivos de aprendizaje

  • Integrar clínicos, sensores, imagen y ómicas para resolver un caso de diseño de flujos para datos biomédicos heterogéneos con evidencia, controles, incertidumbre y comunicación proporcional.
  • Integrar ETL y ELT, validación de esquemas, unidades para resolver un caso de integración reproducible sin perder significado con evidencia, controles, incertidumbre y comunicación proporcional.
  • Integrar relacional, lago de datos, series temporales para resolver un caso de selección de arquitectura según uso y escala con evidencia, controles, incertidumbre y comunicación proporcional.
  • Integrar completitud, consistencia, linaje y versionado para resolver un caso de detección de problemas antes del análisis con evidencia, controles, incertidumbre y comunicación proporcional.
  • Integrar pipelines, pruebas, logs y alertas para resolver un caso de operación confiable de procesos de datos con evidencia, controles, incertidumbre y comunicación proporcional.
  • Integrar seudonimización, acceso, documentación y contratos para resolver un caso de entrega responsable de datasets analíticos con evidencia, controles, incertidumbre y comunicación proporcional.

Resultados de aprendizaje evaluables

  • Explica y relaciona los dominios centrales de Ingeniería de Datos Biomédicos con precisión.
  • Entrega un prototipo reproducible con contrato de datos y plan de validación reproducible y auditable.
  • Resuelve problemas inéditos declarando unidades, supuestos, controles y límites.
  • Compara una explicación principal con alternativas y propone pruebas discriminantes.
  • Evalúa sensibilidad, incertidumbre, riesgo de sesgo y transferibilidad.
  • Corrige un producto después de revisión y justifica cada cambio.
  • Distingue desempeño técnico, validez científica, utilidad y evidencia clínica o regulatoria.

Unidad 1Fuentes y arquitectura de datos

Diseñar y justificar una arquitectura source-to-landing para datos biomédicos heterogéneos —registros clínicos, señales fisiológicas, imagen médica y ómicas— preservando identidad, granularidad, tiempo, unidades y metadatos de adquisición antes de cualquier transformación. La unidad enseña a inventariar fuentes, reconocer su semántica temporal y sus patrones de actualización, y construir un flujo reproducible desde sistemas fuente hacia una zona de aterrizaje sintética; reserva ETL/ELT y conversiones para U2, almacenamiento/modelado para U3, calidad/linaje profundo para U4, orquestación/observabilidad para U5 y privacidad/productos de datos para U6.

Abrir lección → Unidad 2Ingesta y transformación

Diseñar, implementar y auditar transformaciones ETL/ELT reproducibles desde una landing biomédica hacia representaciones normalizadas sin destruir identidad, temporalidad, unidades, códigos ni evidencia de origen. La unidad distingue validación estructural de validación semántica, enseña conversión de unidades con UCUM y contexto explícito, trata cambios de esquema, ausencias, correcciones y rechazos como estados trazables, y exige reconciliación e idempotencia. Reutiliza el inventario source-to-landing de U1; reserva almacenamiento/modelado para U3, calidad/linaje/versionado profundo para U4, orquestación/observabilidad para U5 y privacidad/productos de datos para U6.

Abrir lección → Unidad 3Almacenamiento y modelado

Diseñar y justificar arquitecturas de almacenamiento para datos biomédicos normalizados, separando modelo lógico, formato físico y motor de consulta. La unidad compara tablas relacionales con restricciones explícitas, archivos columnares en lagos de datos y formatos de tabla analítica, y patrones de series temporales/longitudinales según carga de trabajo, escala, mutabilidad y semántica temporal. Enseña claves, normalización y desnormalización controlada, índices, particionado, Parquet, snapshots de tabla, effective/issued/ingest time y benchmarking reproducible. Reutiliza las salidas transformadas de U2; reserva calidad, linaje y versionado profundo para U4, orquestación/observabilidad para U5 y privacidad/productos de datos para U6.

Abrir lección → Unidad 4Calidad y procedencia

Evaluar y documentar la calidad de datos biomédicos antes de su reutilización, convirtiendo conceptos como completitud, conformidad, consistencia, plausibilidad, unicidad y actualidad en comprobaciones reproducibles con denominadores, reglas, umbrales y evidencia. La unidad conecta los contratos y transformaciones de U2 con los modelos, snapshots y semántica temporal de U3; desarrolla procedencia, linaje, versionado y análisis de impacto con W3C PROV, FHIR Provenance y OpenLineage como marcos de referencia. Reserva la ejecución operacional, scheduling, reintentos y observabilidad profunda para U5, y privacidad, autorización y productos de datos para U6. El objetivo no es producir un score universal de calidad, sino un dossier auditable que permita decidir qué usos están respaldados, qué defectos requieren cuarentena o corrección y qué incertidumbres permanecen.

Abrir lección → Unidad 5Orquestación y observabilidad

Operar pipelines biomédicos reproducibles como sistemas temporales observables: modelar DAG, tareas, dependencias, runs e intervalos de datos; diseñar reintentos, backfill e idempotencia sin duplicar efectos; instrumentar logs, métricas y trazas correlacionables; definir SLI, SLO, alertas y criterios de recuperación; y reconstruir incidentes con evidencia de ejecución y linaje. La unidad consume los quality gates, manifests y procedencia de U4, pero no redefine calidad de datos; reserva privacidad, seudonimización, minimización, autorización, controles de acceso, documentación contractual y entrega responsable de productos de datos para U6. Todo el trabajo usa pipelines y datasets sintéticos, sin acceso a EHR, PACS, LIS, credenciales ni infraestructura clínica real.

Abrir lección → Unidad 6Privacidad y productos de datos

Diseñar y gobernar un producto de datos biomédicos sintético que minimice exposición y riesgo de reidentificación, documente finalidad, semántica, acceso, retención y versión, y pueda entregarse con un contrato técnico verificable y controles de autorización trazables. La unidad integra contratos, almacenamiento, calidad, procedencia y observabilidad de U1–U5 sin redefinirlos; distingue seudonimización de anonimización, autenticación de autorización y un data contract técnico de un acuerdo jurídico de uso. Todas las actividades emplean datos sintéticos o no identificables y no constituyen evaluación jurídica, DPIA, certificación de cumplimiento ni autorización para tratar datos clínicos reales.
