Desarrollo 1

De la necesidad asistencial al uso previsto

Un proyecto de machine learning biomédico no comienza con un algoritmo ni con una base de datos disponible. Comienza con una decisión concreta dentro de un flujo asistencial. El uso previsto debe indicar quién utilizará la salida, sobre qué población, en qué entorno, en qué momento y para apoyar qué acción. Predecir deterioro en urgencias no es el mismo problema que priorizar camas, decidir una prueba adicional o informar pronóstico a una familia. Aunque puedan compartir desenlace, las consecuencias, tolerancias y variables disponibles son diferentes.

El momento índice o tiempo cero es el punto desde el cual se produce la predicción. Todo predictor debe existir o ser obtenible en ese momento. Incorporar información posterior, como tratamientos administrados, resultados confirmatorios o mediciones registradas tras el evento, genera fuga temporal. El horizonte define cuánto tiempo hacia adelante se estima el desenlace. Un riesgo a seis horas, treinta días o cinco años implica procesos biológicos, prevalencias y acciones distintas. La población objetivo debe expresar inclusiones, exclusiones y condiciones de aplicabilidad.

El contexto de uso también delimita qué rendimiento sería aceptable. Un sistema de triaje puede tolerar más falsos positivos que un sistema que evita una intervención necesaria. La capacidad del servicio, la prueba confirmatoria y la posibilidad de revisión humana forman parte del problema. El protocolo debe describir qué ocurre con la salida, qué alternativa existe cuando el modelo no responde y qué daño podría causar un error. Sin estas definiciones, ninguna métrica permite juzgar si el modelo aporta valor.

Puntos de integración

  • El algoritmo se selecciona después de definir la decisión clínica.
  • Tiempo cero y horizonte determinan qué información es admisible.
  • La población objetivo debe corresponder al entorno de uso.
  • El coste de los errores depende de la acción que sigue a la predicción.

Desarrollo 2

Predicción, diagnóstico, pronóstico y causalidad

Un modelo diagnóstico estima la presencia de una condición en un momento definido, mientras un modelo pronóstico estima un resultado futuro. Ambos son predictivos, pero la referencia, la secuencia temporal y las acciones asociadas difieren. Una clasificación retrospectiva puede distinguir grupos en datos históricos sin representar un uso prospectivo. Por ejemplo, separar pacientes que recibieron un tratamiento de quienes no lo recibieron puede aprender decisiones clínicas previas, no una necesidad biológica ni un beneficio futuro.

La predicción tampoco estima automáticamente efectos causales. Un predictor puede mejorar el pronóstico sin ser modificable ni causal. Del mismo modo, una asociación entre tratamiento y desenlace no indica qué ocurriría al asignar el tratamiento, porque la indicación clínica, gravedad y otros factores influyen en ambas variables. Si la pregunta es quién se beneficiará de una intervención, se necesita un contraste causal o de efecto heterogéneo, no solo un modelo que prediga el desenlace observado.

La separación entre predicción y causalidad protege la interpretación. Edad, código postal o frecuencia de visitas pueden ser útiles para anticipar un resultado, pero pueden actuar como proxies de acceso, práctica local o desigualdad. El modelo puede ser operacionalmente predictivo y aun así inadecuado para decidir recursos o tratamientos. El protocolo debe declarar qué tipo de inferencia busca, qué afirmaciones quedan fuera de alcance y qué evidencia adicional sería necesaria para cambiar la práctica.

Puntos de integración

  • Diagnóstico y pronóstico son problemas predictivos con tiempos distintos.
  • Clasificar datos históricos no garantiza utilidad prospectiva.
  • Importancia predictiva no equivale a mecanismo causal.
  • Decidir tratamientos requiere preguntas causales adicionales.

Desarrollo 3

Desenlace, horizonte, unidad de análisis y competidores

El desenlace debe definirse con criterios observables, periodo de evaluación y proceso de confirmación. Etiquetas como complicación, respuesta o deterioro son insuficientes si distintos centros las interpretan de manera diferente. Debe declararse si el desenlace proviene de laboratorio, revisión clínica, código administrativo, adjudicación o combinación de fuentes. También importa si la medición del desenlace está disponible para todos o solo para quienes recibieron una prueba, porque esto puede introducir sesgo de verificación.

La unidad de análisis debe coincidir con la independencia relevante. Un paciente puede aportar múltiples visitas, estudios o ventanas temporales; tratarlas como observaciones independientes altera la incertidumbre y facilita que el mismo individuo aparezca en desarrollo y evaluación. En modelos longitudinales deben definirse ventanas, actualización de predictores y reglas para eventos repetidos. Cuando existe muerte, alta u otro evento que impide observar el desenlace principal, se deben considerar riesgos competitivos y censura.

El horizonte cambia el significado clínico. Una predicción muy cercana puede capturar señales del evento ya iniciado, mientras una predicción lejana puede ser menos precisa pero permitir intervención. La elección debe equilibrar anticipación, acción y fiabilidad. Debe evitarse seleccionar el horizonte después de observar cuál produce la mejor AUC. Los horizontes y umbrales exploratorios pueden estudiarse, pero el objetivo principal debe preespecificarse para reducir decisiones oportunistas.

Puntos de integración

  • El desenlace necesita una definición reproducible y una fuente conocida.
  • Múltiples registros por paciente no son observaciones independientes.
  • Riesgos competitivos y censura modifican el problema pronóstico.
  • El horizonte debe permitir una acción clínicamente plausible.

Desarrollo 4

Estimando predictivo, protocolo y criterio de éxito

El estimando predictivo describe exactamente qué cantidad se desea estimar y en qué población. Puede ser una probabilidad individual, un tiempo hasta evento, una clase, una puntuación continua o una recomendación. Debe incluir momento de predicción, horizonte, predictores admisibles, tratamiento de eventos competidores y condiciones de uso. Esta especificación evita que el proyecto cambie silenciosamente de objetivo cuando aparecen dificultades o resultados desfavorables.

El protocolo también define comparadores. El modelo candidato debe evaluarse frente a una práctica existente, una regla clínica o un baseline simple. Superar el azar no es un criterio útil. Si una regresión con pocas variables logra desempeño similar a un modelo complejo, la comparación debe considerar calibración, mantenimiento, transparencia, latencia y coste. El criterio de éxito puede incluir no inferioridad, reducción de carga, mejora de net benefit o detección más temprana, no solo un incremento de AUC.

La preespecificación no impide explorar. Se pueden comparar variables, algoritmos y horizontes, pero deben diferenciarse análisis confirmatorios y exploratorios. TRIPOD+AI promueve reportar claramente cómo se definieron datos, modelo y evaluación. Un protocolo sólido permite reconocer cuándo el problema no es resoluble con los datos disponibles, cuándo la decisión no necesita un modelo y cuándo una intervención organizativa sería más directa que añadir una predicción.

Puntos de integración

  • El estimando fija la cantidad predictiva y las condiciones de uso.
  • El comparador debe representar la práctica o un baseline relevante.
  • El éxito no se reduce a mejorar AUC.
  • Un resultado negativo puede indicar que el modelo no es la intervención adecuada.

Ejemplos y casos resueltos

Alerta de sepsis con tiempo cero incorrecto

Situación. Un modelo usa el resultado de un cultivo disponible dos días después para predecir sepsis al ingreso.

Razonamiento paso a paso

  1. Definir el momento real de la alerta.
  2. Listar variables disponibles en ese momento.
  3. Eliminar información posterior.
  4. Reformular desenlace y horizonte.

Interpretación. El desempeño original estaba inflado por fuga temporal y no representaba uso prospectivo.

Limitaciones

  • La nueva etiqueta puede seguir siendo imperfecta.
  • El flujo local puede retrasar otras variables.

Predicción de respuesta confundida con efecto terapéutico

Situación. Un modelo predice buen resultado entre pacientes que recibieron un fármaco y se propone usarlo para decidir quién debe recibirlo.

Razonamiento paso a paso

  1. Separar pronóstico observado de efecto del tratamiento.
  2. Identificar confusión por indicación.
  3. Definir el contraste causal requerido.
  4. Limitar la afirmación predictiva.

Interpretación. Predecir el desenlace bajo la práctica observada no identifica beneficio individual del tratamiento.

Limitaciones

  • Puede requerirse un ensayo o diseño causal.
  • Los predictores pueden cambiar tras modificar la práctica.

Actividad aplicada

Protocolo de una predicción clínica

Procedimiento

  1. Elegir una decisión biomédica concreta.
  2. Definir población, usuario, tiempo cero y horizonte.
  3. Especificar desenlace y predictores disponibles.
  4. Seleccionar baseline y criterio de éxito.

Problemas y tareas

  • Distinguir una pregunta diagnóstica de una pronóstica.
  • Detectar tres variables que producirían fuga temporal.
  • Redactar un uso previsto completo para una alerta hospitalaria.
  • Definir una unidad de análisis cuando existen visitas repetidas.
  • Proponer un horizonte que permita intervención y justificarlo.
  • Separar una pregunta predictiva de una causal sobre tratamiento.
  • Elegir un baseline clínico razonable.
  • Definir criterios de éxito más allá de AUC.

Criterios de comprobación

  • El tiempo cero es inequívoco.
  • Los predictores son temporalmente admisibles.
  • El desenlace es reproducible.
  • La acción y el comparador están explícitos.

Errores frecuentes y autoevaluación

Errores frecuentes y corrección

  • Comenzar por el algoritmo disponible.

    Definir primero decisión, población, momento y comparador.

  • Usar variables posteriores al tiempo cero.

    Auditar disponibilidad temporal de cada predictor.

  • Confundir pronóstico con efecto terapéutico.

    Separar predicción observacional de contrastes causales.

  • Tratar registros repetidos como independientes.

    Definir unidad de análisis y agrupar por paciente.

  • Definir éxito solo como AUC alta.

    Incluir calibración, utilidad, flujo, daño y comparación con la práctica.

1. ¿Qué elementos contiene el uso previsto?

Respuesta: Usuario, población, entorno, momento, salida y decisión apoyada.

2. ¿Por qué importa el tiempo cero?

Respuesta: Determina qué variables existen legítimamente al predecir.

3. ¿Qué diferencia hay entre diagnóstico y pronóstico?

Respuesta: El primero estima una condición presente; el segundo un resultado futuro.

4. ¿Una variable predictiva es necesariamente causal?

Respuesta: No; puede ser proxy, marcador o consecuencia de otros procesos.

5. ¿Qué problema producen visitas repetidas?

Respuesta: Dependencia y posible fuga si el paciente aparece en varias particiones.

6. ¿Qué es un riesgo competitivo?

Respuesta: Un evento que impide o altera la observación del desenlace principal.

7. ¿Por qué se necesita un baseline?

Respuesta: Para estimar valor incremental frente a una alternativa realista.

8. ¿Cuándo no conviene construir un modelo?

Respuesta: Cuando no existe una decisión clara, los datos no representan el uso o una intervención directa resuelve mejor el problema.

Glosario disciplinar

  • Uso previsto

    Descripción de usuario, población, entorno, momento, salida y decisión apoyada.

  • Tiempo cero

    Momento desde el cual se realiza la predicción y se define la disponibilidad de variables.

  • Horizonte

    Intervalo futuro dentro del cual se evalúa el desenlace.

  • Estimando predictivo

    Cantidad predictiva definida para una población, tiempo y condiciones concretas.

  • Modelo diagnóstico

    Modelo que estima una condición presente o contemporánea.

  • Modelo pronóstico

    Modelo que estima un resultado futuro.

  • Fuga temporal

    Uso de información que aparece después del momento previsto de predicción.

  • Predictor

    Variable disponible para generar una predicción individual.

  • Desenlace

    Resultado cuya presencia, valor o tiempo se pretende estimar.

  • Riesgo competitivo

    Evento que impide o modifica la observación del evento principal.

  • Baseline

    Referente simple o práctica existente contra la cual se compara el modelo.

  • Aplicabilidad

    Correspondencia entre datos, población, entorno y uso previsto del modelo.
