Desarrollo 1

Discretización y método de Euler

Un integrador reemplaza la evolución continua por pasos finitos. Euler explícito usa la pendiente al inicio del paso para avanzar. Es transparente y pedagógico, pero su error global es de primer orden y puede ser inestable incluso cuando la solución exacta decae.

Reducir el paso suele disminuir el error, pero aumenta coste y no corrige una formulación errónea. Una prueba de refinamiento compara soluciones con pasos sucesivamente menores y estima el orden observado. Sin referencia exacta, la convergencia interna es evidencia de verificación, no de validez del modelo.

Euler puede violar positividad y conservación. Para x'=-kx, el avance es positivo solo si 1-kh es no negativo. Esta restricción muestra cómo propiedades numéricas dependen del producto entre paso y escala dinámica.

Puntos de integración

  • Euler aproxima con la pendiente inicial.
  • Refinamiento evalúa error de discretización.
  • El paso puede violar positividad o estabilidad.

Desarrollo 2

Runge–Kutta y control adaptativo

Los métodos Runge–Kutta evalúan varias pendientes dentro del paso para lograr mayor orden sin derivadas analíticas superiores. RK4 es útil en enseñanza, pero los solucionadores modernos emplean pares embebidos que estiman error y adaptan el paso.

Las tolerancias absoluta y relativa definen una escala de error aceptada por componente. Una tolerancia única puede ser inadecuada si los estados tienen magnitudes muy distintas. Escalar variables o configurar tolerancias por estado evita que una variable grande domine el control.

El controlador de paso no conoce la verdad biológica; solo estima error numérico según el algoritmo. Tolerancias muy estrictas pueden gastar recursos sin mejorar la discrepancia estructural, mientras tolerancias laxas pueden alterar eventos o parámetros ajustados.

Puntos de integración

  • Runge–Kutta combina pendientes internas.
  • Las tolerancias deben reflejar escalas de estado.
  • Error numérico y error del modelo son distintos.

Desarrollo 3

Estabilidad absoluta, rigidez y eventos

Una región de estabilidad absoluta describe para qué valores de hλ un método reproduce decaimiento en la ecuación de prueba. Un método de alto orden puede ser inestable con pasos grandes. La selección de algoritmo requiere considerar espectro y escalas.

Un sistema rígido contiene modos rápidos que restringen el paso explícito aunque el interés esté en modos lentos. Métodos implícitos permiten pasos mayores, pero requieren resolver ecuaciones algebraicas y Jacobianos. Rigidez es una relación entre problema y método, no una etiqueta visual.

Los eventos localizan cruces de umbral, máximos o cambios de régimen. Deben definirse con dirección y tolerancia para evitar detecciones múltiples. Introducir discontinuidades exige reiniciar adecuadamente el integrador y conservar el estado.

Puntos de integración

  • La estabilidad depende de hλ.
  • Rigidez combina escalas y algoritmo.
  • Los eventos requieren definición numérica precisa.

Desarrollo 4

Verificación, pruebas y reproducibilidad

Verificar software significa comprobar que las ecuaciones se resuelven como se pretendía. Se usan soluciones exactas, casos límite, conservación, positividad, comparación entre métodos y pruebas unitarias. Validar significa confrontar el modelo con el sistema real; son tareas diferentes.

Un notebook reproducible declara versión del entorno, tolerancias, parámetros, condiciones iniciales, semilla y fuente de datos. Las figuras deben poder regenerarse desde cero. Guardar solo una imagen impide auditar el cálculo.

Las pruebas de regresión detectan cambios inesperados al modificar código. No deben fijar un resultado incorrecto como verdad; se combinan con referencias analíticas y propiedades. La revisión final incluye sensibilidad a tolerancias y plataforma cuando la precisión es crítica.

Puntos de integración

  • Verificación responde si se resolvió bien; validación, si el modelo representa el sistema.
  • El entorno forma parte del experimento computacional.
  • Las pruebas deben apoyarse en propiedades independientes.

Desarrollo 5

Protocolo de verificación de una simulación

Una simulación se considera verificada cuando supera una batería de pruebas, no cuando produce una figura suave. Se compara con una solución exacta o manufacturada, se realiza refinamiento, se comprueban invariantes y se examinan eventos. Cada prueba ataca una clase distinta de error.

El error de programación puede compensarse accidentalmente con un error de discretización. Por eso se comparan implementaciones independientes o bibliotecas maduras y se usan casos simples con respuesta conocida. Una coincidencia puntual no sustituye una curva de convergencia.

En sistemas rígidos, la tolerancia y el Jacobiano afectan coste y precisión. Se registran número de pasos, rechazos y evaluaciones, además del resultado. Un método que produce la misma curva con cien veces más trabajo puede ser inadecuado para inferencia repetida.

La entrega final incluye un archivo de entorno, pruebas automáticas y una tabla que separa error numérico, incertidumbre de parámetros y discrepancia del modelo. Esta separación previene la práctica de reducir tolerancias para ocultar un desacuerdo que en realidad es científico.

Puntos de integración

  • La verificación combina pruebas independientes.
  • Errores distintos pueden compensarse.
  • El coste forma parte de la selección de método.
  • Las fuentes de incertidumbre se reportan por separado.

Desarrollo 6

Selección de solucionador y trazabilidad del cálculo

No existe un integrador universalmente mejor. Un problema no rígido con eventos puede favorecer un Runge–Kutta adaptativo; uno rígido puede requerir BDF o Radau; un sistema con estructura hamiltoniana puede necesitar métodos que preserven geometría. La elección se documenta según propiedades, no por costumbre.

Los valores por defecto de una biblioteca pueden cambiar entre versiones. Por ello se registran método, tolerancias, Jacobiano, densidad de salida y tratamiento de eventos. La reproducibilidad exige más que el nombre de la función usada.

En inferencia, el error del solucionador debe ser suficientemente menor que la variación que guía la función objetivo. Si el error numérico cambia con parámetros, puede deformar la superficie de optimización. Se prueba estabilidad de estimaciones frente a tolerancias y métodos alternativos.

La precisión se reporta junto con coste computacional y propiedades preservadas. Un método que converge en una norma puede fallar en tiempos de evento o máximos, por lo que la verificación incluye las cantidades que realmente sustentan la conclusión.

Puntos de integración

  • La elección depende de las propiedades del problema.
  • Los parámetros del solucionador forman parte del método.
  • La inferencia puede ser sensible al error del integrador.

Ejemplos y casos resueltos

Refinamiento de Euler

Situación. Resolver x'=-10x, x(0)=1 hasta t=1.

Razonamiento paso a paso

  1. Probar h=0.2,0.1,0.05.
  2. Detectar inestabilidad o error.
  3. Comparar con e^-10.
  4. Estimar orden.

Interpretación. Un paso grande puede oscilar o cambiar signo.

Limitaciones

  • El resultado depende de los supuestos y del rango donde se aplica el modelo.
  • La coincidencia matemática no demuestra por sí sola utilidad clínica ni mecanismo completo.

Evento de umbral

Situación. Integrar una concentración hasta cruzar 5 unidades.

Razonamiento paso a paso

  1. Definir función de evento.
  2. Especificar dirección.
  3. Usar interpolación del solucionador.
  4. Comprobar tolerancia con refinamiento.

Interpretación. Muestrear solo la salida puede sesgar el evento.

Limitaciones

  • El resultado depende de los supuestos y del rango donde se aplica el modelo.
  • La coincidencia matemática no demuestra por sí sola utilidad clínica ni mecanismo completo.

Glosario disciplinar

  • Discretización

    Sustitución de un continuo por pasos, nodos o elementos finitos para calcular una aproximación.

  • Paso temporal

    Intervalo usado entre actualizaciones sucesivas de un método numérico.

  • Error local

    Error introducido en un solo paso suponiendo exacto el estado de partida.

  • Error global

    Diferencia acumulada entre solución numérica y exacta a lo largo de varios pasos.

  • Orden

    Potencia con la que disminuye el error de un método al refinar el paso.

  • Runge–Kutta

    Familia de integradores que combina varias evaluaciones de pendiente dentro de cada paso.

  • Tolerancia absoluta

    Límite de error referido a la escala absoluta de un estado.

  • Tolerancia relativa

    Límite de error proporcional a la magnitud del estado.

  • Estabilidad absoluta

    Conjunto de pasos y autovalores para los que un método numérico reproduce decaimiento de la ecuación de prueba.

  • Rigidez

    Situación en la que modos rápidos restringen fuertemente métodos explícitos aunque interesen escalas lentas.

  • Evento

    Condición definida durante la integración que localiza un cruce, máximo o cambio de régimen.

  • Verificación

    Comprobación de que las ecuaciones y algoritmos se implementaron y resolvieron correctamente.
