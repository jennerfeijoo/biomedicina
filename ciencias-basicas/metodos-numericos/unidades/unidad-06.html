Desarrollo teórico

Los conceptos se estudian mediante mecanismos, modelos, evidencia, supuestos y límites de interpretación.

Desarrollo 1

Jerarquía de verificación y oráculos

La verificación responde si las ecuaciones discretizadas y el software se resuelven como se pretende. Puede dividirse en verificación de código y verificación de cálculo.

Un oráculo puede ser una solución analítica, identidad, conservación, problema simplificado, aritmética de alta precisión o implementación independiente. Ningún oráculo es universal; su independencia debe evaluarse.

Las soluciones manufacturadas eligen una solución suave y derivan el término fuente requerido. Permiten probar orden y condiciones de frontera sin depender de un problema con solución natural cerrada.

La concordancia visual es evidencia débil. Deben cuantificarse normas, órdenes, residuales y tolerancias con criterios definidos antes de observar el resultado.

Puntos de integración

  • Verificación de código y cálculo son distintas
  • Los oráculos tienen límites
  • Las soluciones manufacturadas prueban implementación
  • La evidencia debe ser cuantitativa

Desarrollo 2

Pruebas de software científico

Las pruebas unitarias cubren funciones pequeñas y casos conocidos. Las pruebas de integración cubren el flujo completo, formatos, unidades y persistencia de resultados.

Las pruebas basadas en propiedades generan entradas para verificar invariantes como simetría, monotonía, conservación o equivalencia bajo transformaciones válidas. El generador debe respetar el dominio matemático.

Metamorphic testing relaciona resultados cuando no existe un oráculo puntual: reescalar, permutar o refinar puede inducir relaciones esperadas. Una relación mal definida produce falsos seguros.

Tolerancias de pruebas deben justificarse por condición, escala y precisión. Comparaciones bit a bit pueden ser inapropiadas entre hardware o bibliotecas, mientras tolerancias laxas ocultan regresiones.

Puntos de integración

  • Unitarias e integración cubren niveles distintos
  • Las propiedades requieren dominio válido
  • Metamorphic testing usa relaciones
  • Las tolerancias deben justificarse

Desarrollo 3

Sensibilidad, incertidumbre y validación

La sensibilidad numérica estudia cambios ante paso, tolerancia, precisión o algoritmo. La sensibilidad paramétrica estudia cambios ante entradas o parámetros del modelo.

La incertidumbre aleatoria puede propagarse mediante muestreo; la epistémica incluye estructura, calibración y decisiones de modelado. Un único intervalo no debe mezclar fuentes sin explicación.

Validar compara resultados del modelo con evidencia independiente del fenómeno de interés. Un software verificado puede implementar exactamente un modelo que no reproduce la realidad.

En biomedicina, utilidad clínica exige evaluación adicional de población, flujo, umbrales, seguridad y consecuencias. Este curso se limita a verificación numérica y comunicación responsable.

Puntos de integración

  • Sensibilidad numérica y paramétrica son distintas
  • La incertidumbre tiene fuentes múltiples
  • Verificación no es validación
  • Utilidad clínica requiere evidencia externa

Desarrollo 4

Benchmarks, procedencia y entrega reproducible

Un benchmark define problema, tamaño, precisión, tolerancia, hardware, software, warm-up, repeticiones y estadística de tiempo. Cambiar cualquiera de estos elementos puede alterar la conclusión.

El rendimiento debe relacionarse con error y coste total, incluyendo preprocesamiento, compilación, precondicionadores y transferencia de datos. Acelerar una parte no garantiza acelerar el pipeline.

La procedencia registra versiones, parámetros, semillas, datos, transformaciones y artefactos. Un entorno declarativo y una ejecución automatizada reducen ambigüedad.

La reproducibilidad computacional permite repetir resultados bajo condiciones documentadas; no garantiza replicación científica en nuevos datos ni validez clínica.

Puntos de integración

  • Benchmark exige contrato
  • El coste total importa
  • La procedencia es parte del resultado
  • Reproducibilidad no equivale a replicación científica

Ejemplos y casos resueltos

Solución manufacturada para difusión 1D

Situación. Verificar una discretización educativa con fuente y fronteras derivadas.

Razonamiento paso a paso

  1. Elegir solución suave positiva.
  2. Derivar fuente y condiciones.
  3. Resolver en mallas sucesivas.
  4. Calcular normas y orden observado.

Interpretación. El orden esperado apoya la implementación en el régimen probado.

Limitaciones

  • No prueba todas las ramas del código.
  • No valida transporte tisular real.

Benchmark de pipeline de calibración

Situación. Comparar dos implementaciones con igual precisión objetivo.

Razonamiento paso a paso

  1. Definir datos sintéticos y oráculo.
  2. Fijar tolerancias y entorno.
  3. Medir error, tiempo y memoria con repeticiones.
  4. Ejecutar sensibilidad a tamaño y condición.

Interpretación. La implementación más rápida depende del régimen y la exactitud exigida.

Limitaciones

  • Hardware específico.
  • No certifica software médico.

Errores frecuentes y autoevaluación

Errores frecuentes y corrección

  • Usar concordancia visual como verificación.

    Cuantificar error, residual y orden.

  • Probar solo casos nominales.

    Añadir fronteras, entradas adversariales y fallas esperadas.

  • Elegir tolerancias para que la prueba pase.

    Derivarlas de escala, condición y referencia.

  • Comparar rendimiento con distinta exactitud.

    Igualar error objetivo y contrato.

  • Confundir CI verde con corrección científica.

    CI ejecuta pruebas; la calidad depende de los oráculos y cobertura.

  • Llamar validado a un modelo solo verificado.

    Reservar validación para comparación independiente con realidad.

1. ¿Qué verifica una solución manufacturada?

Respuesta: Implementación, orden y fronteras en un caso controlado.

2. ¿Qué diferencia código y cálculo?

Respuesta: Implementación general frente al error de una ejecución concreta.

3. ¿Qué es una prueba metamórfica?

Respuesta: Una relación esperada entre ejecuciones transformadas.

4. ¿CI verde prueba ciencia correcta?

Respuesta: No; solo confirma las pruebas configuradas.

5. ¿Qué debe igualar un benchmark?

Respuesta: Problema, precisión, tolerancias y entorno pertinente.

6. ¿Sensibilidad numérica y paramétrica son iguales?

Respuesta: No.

7. ¿Verificación basta para validar?

Respuesta: No.

8. ¿Reproducibilidad implica utilidad clínica?

Respuesta: No.

Glosario disciplinar

  • Verificación de código

    Comprobación de que el software implementa correctamente el método.

  • Verificación de cálculo

    Cuantificación del error de una simulación concreta.

  • Validación

    Comparación del modelo con evidencia del fenómeno real.

  • Oráculo

    Referencia usada para juzgar un resultado.

  • Solución manufacturada

    Solución elegida para derivar un problema controlado.

  • Refinamiento

    Reducción sistemática de paso, malla o tolerancia.

  • Orden observado

    Tasa empírica de disminución del error.

  • Property-based testing

    Pruebas generativas de propiedades generales.

  • Metamorphic testing

    Pruebas de relaciones entre ejecuciones transformadas.

  • Regresión de software

    Pérdida de comportamiento previamente verificado.

  • Sensibilidad

    Cambio de salida ante perturbaciones.

  • Incertidumbre

    Rango o distribución de resultados plausibles.

  • Benchmark

    Comparación bajo un protocolo especificado.

  • Procedencia

    Registro trazable de datos, código, entorno y decisiones.
